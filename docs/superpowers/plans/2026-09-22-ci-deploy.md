- [ ] **Step 1: Write `backend/migrate.py`**

```python
"""Migration job entrypoint: `alembic upgrade head`, then exit.

Runs in the `ai-enablement-hub-migrate` Container Apps Job BEFORE each deploy rolls the app
(see .github/workflows/deploy.yml). The app container itself never migrates (startup.py).
Uses the Alembic Python API because the image has no shell entrypoint conventions to rely on.
Exit code is the contract: 0 = schema at head, non-zero = the deploy must not proceed.
"""

from __future__ import annotations

import sys

from alembic.config import Config
from alembic.runtime.migration import MigrationContext
from alembic.script import ScriptDirectory
from sqlalchemy import create_engine

from alembic import command

__all__ = ["main"]


def _current_heads(cfg: Config) -> tuple[str, ...]:
    """Read the DB's current revision(s) with a short-lived sync engine (asyncpg URL -> psycopg-free
    check is not available, so reuse Alembic's own env by asking it for the script head instead)."""
    url = cfg.get_main_option("sqlalchemy.url")
    if not url:
        return ()
    sync_url = url.replace("+asyncpg", "")
    engine = create_engine(sync_url)
    try:
        with engine.connect() as conn:
            return tuple(MigrationContext.configure(conn).get_current_heads())
    finally:
        engine.dispose()


def main() -> int:
    cfg = Config("alembic.ini")
    script_head = ScriptDirectory.from_config(cfg).get_current_head()
    print(f"[migrate] code head: {script_head}", flush=True)
    try:
        command.upgrade(cfg, "head")
    except Exception as exc:  # noqa: BLE001 - the exit code is the contract
        print(f"[migrate] FAILED: {exc!r}", flush=True)
        return 1
    print("[migrate] upgrade head: done", flush=True)
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

Check how `alembic/env.py` obtains its URL: run `grep -n "ALEMBIC_DATABASE_URL\|sqlalchemy.url\|set_main_option" backend/alembic/env.py backend/alembic.ini`. ### Task 4: The Deploy workflow

**Files:**
- Create: `.github/workflows/deploy.yml`

- [ ] **Step 1: Write the workflow**

```yaml
# Deploy — manual button (Actions tab -> Deploy -> Run workflow), main only.
#
# What it does, in order, and stops at the first failure:
#   1. resolve the commit (main HEAD, or an existing image by SHA for rollback)
#   2. OIDC login to Azure as the user-assigned identity ai-hub-cicd (no stored secret)
#   3. docker build + push  ca530fc7463eacr.azurecr.io/ai-enablement-hub:<sha>   (skipped on rollback)
#   4. run the DB migration in the Container Apps Job ai-enablement-hub-migrate and WAIT — fail-closed
#   5. roll the app to the image, stamping APP__BUILD_SHA / APP__BUILD_TIME
#   6. poll until the new revision reports that image and Running
#   7. read /api/health back and assert build_sha == sha
#
# Never runs on merge: Matthias decided deploys stay a deliberate act (spec 2026-09-22 §0).
# The federated credential's subject is bound to refs/heads/main, so a dispatch from any other
# ref would fail at login; the `if:` below makes that explicit and early.
# All inputs reach scripts via env:, never via ${{ }} inside run: (script-injection hygiene).
name: Deploy

on:
  workflow_dispatch:
    inputs:
      image_sha:
        description: "Rollback: full 40-char commit SHA of an image that already exists in ACR. Leave empty to build and deploy main HEAD."
        required: false
        default: ""

permissions:
  contents: read
  id-token: write

concurrency:
  group: deploy-production
  cancel-in-progress: false

env:
  RESOURCE_GROUP: imaginemore-playground
  APP_NAME: ai-enablement-hub
  JOB_NAME: ai-enablement-hub-migrate
  ACR_NAME: ca530fc7463eacr
  ACR_LOGIN_SERVER: ca530fc7463eacr.azurecr.io
  IMAGE_REPO: ai-enablement-hub
  IMAGE_SHA_INPUT: ${{ inputs.image_sha }}
  GITHUB_SHA_ENV: ${{ github.sha }}

jobs:
  deploy:
    name: build, migrate, roll, verify
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0   # merge-base check for rollback SHAs

      - name: Resolve target SHA
        id: resolve
        run: |
          set -euo pipefail
          if [ -n "$IMAGE_SHA_INPUT" ]; then
            if ! printf '%s' "$IMAGE_SHA_INPUT" | grep -Eq '^[0-9a-f]{40}$'; then
              echo "::error::image_sha must be a full 40-char lowercase SHA"; exit 1
            fi
            if ! git merge-base --is-ancestor "$IMAGE_SHA_INPUT" HEAD; then
              echo "::error::$IMAGE_SHA_INPUT is not an ancestor of main — refusing to deploy a side-branch image"; exit 1
            fi
            echo "sha=$IMAGE_SHA_INPUT" >> "$GITHUB_OUTPUT"
            echo "build=false" >> "$GITHUB_OUTPUT"
            echo "Rollback/redeploy of existing image $IMAGE_SHA_INPUT"
          else
            echo "sha=$GITHUB_SHA_ENV" >> "$GITHUB_OUTPUT"
            echo "build=true" >> "$GITHUB_OUTPUT"
            echo "Build and deploy main HEAD $GITHUB_SHA_ENV"
          fi

      - uses: azure/login@v2
        with:
          client-id: ${{ vars.AZURE_CLIENT_ID }}
          tenant-id: ${{ vars.AZURE_TENANT_ID }}
          subscription-id: ${{ vars.AZURE_SUBSCRIPTION_ID }}

      - name: ACR login
        run: az acr login --name "$ACR_NAME"

      - name: Assert image exists (rollback only)
        if: steps.resolve.outputs.build == 'false'
        env:
          SHA: ${{ steps.resolve.outputs.sha }}
        run: |
          set -euo pipefail
          if ! az acr repository show-tags --name "$ACR_NAME" --repository "$IMAGE_REPO" -o tsv | grep -qx "$SHA"; then
            echo "::error::no image tagged $SHA in $ACR_LOGIN_SERVER/$IMAGE_REPO"; exit 1
          fi

      - name: Build and push image
        if: steps.resolve.outputs.build == 'true'
        env:
          SHA: ${{ steps.resolve.outputs.sha }}
        run: |
          set -euo pipefail
          IMAGE="$ACR_LOGIN_SERVER/$IMAGE_REPO:$SHA"
          docker build -t "$IMAGE" .
          docker push "$IMAGE"
          echo "Pushed $IMAGE"

      - name: Run DB migration job (fail-closed)
        env:
          SHA: ${{ steps.resolve.outputs.sha }}
        run: |
          set -euo pipefail
          IMAGE="$ACR_LOGIN_SERVER/$IMAGE_REPO:$SHA"
          az extension add --name containerapp --upgrade --only-show-errors
          # --command/--args take one value each for `containerapp job`; the entry point is
          # backend/migrate.py, declared here from git on every run.
          az containerapp job update -g "$RESOURCE_GROUP" -n "$JOB_NAME" --image "$IMAGE" \
            --command python --args migrate.py --only-show-errors >/dev/null
          exec_name=$(az containerapp job start -g "$RESOURCE_GROUP" -n "$JOB_NAME" --query name -o tsv)
          echo "Started migration execution $exec_name"
          for i in $(seq 1 20); do
            status=$(az containerapp job execution show -g "$RESOURCE_GROUP" -n "$JOB_NAME" \
              --job-execution-name "$exec_name" --query properties.status -o tsv)
            echo "  [$i] $status"
            case "$status" in
              Succeeded) echo "Migration succeeded"; echo "exec=$exec_name" >> "$GITHUB_OUTPUT"; exit 0 ;;
              Failed|Degraded|Stopped)
                echo "::error::Migration execution $exec_name ended with $status — app NOT rolled"
                az containerapp job logs show -g "$RESOURCE_GROUP" -n "$JOB_NAME" --execution "$exec_name" \
                  --container "$JOB_NAME" --tail 100 --only-show-errors || true
                exit 1 ;;
            esac
            sleep 15
          done
          echo "::error::Migration execution $exec_name did not finish within 5 min — app NOT rolled"; exit 1

      - name: Roll the app
        env:
          SHA: ${{ steps.resolve.outputs.sha }}
        run: |
          set -euo pipefail
          IMAGE="$ACR_LOGIN_SERVER/$IMAGE_REPO:$SHA"
          BUILD_TIME=$(date -u +%Y-%m-%dT%H:%M:%SZ)
          # --set-env-vars is additive: every other env var and secret ref is preserved.
          az containerapp update -g "$RESOURCE_GROUP" -n "$APP_NAME" --image "$IMAGE" \
            --set-env-vars "APP__BUILD_SHA=$SHA" "APP__BUILD_TIME=$BUILD_TIME" --only-show-errors >/dev/null
          echo "BUILD_TIME=$BUILD_TIME" >> "$GITHUB_ENV"
          echo "Update issued for $IMAGE at $BUILD_TIME"

      - name: Wait for the new revision to be healthy

            fi
            sleep 15
          done
          echo "::error::New revision did not become healthy within 10 min (previous revision keeps serving)"; exit 1

        env:
          SHA: ${{ steps.resolve.outputs.sha }}
        run: |
          set -euo pipefail
          fqdn=$(az containerapp show -g "$RESOURCE_GROUP" -n "$APP_NAME" --query properties.configuration.ingress.fqdn -o tsv)
          for i in $(seq 1 10); do

                echo ""
                echo "- image: \`$ACR_LOGIN_SERVER/$IMAGE_REPO:$SHA\`"
                echo "- revision: \`$REVISION\`"
                echo "- build time: \`$BUILD_TIME\`"
                echo "- health: \`$body\`"
              } >> "$GITHUB_STEP_SUMMARY"
              echo "Health reports $live — done"; exit 0
            fi
            echo "  [$i] health build_sha=$live (want $SHA)"; sleep 6
          done
          echo "::error::/api/health does not report $SHA after the roll"; exit 1
```
